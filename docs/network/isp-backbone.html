运营商内部：地址怎么分下来，包怎么跨城跨网

全流程那一页里，包从家里出去要过 6 台路由器，中间 4 台是运营商的。这一页把它们展开：运营商的网怎么分层，地址从哪来、怎么一级级分到你家，别的网怎么知道这些地址在这里，包在骨干网里怎么按标签转发，又怎么从一家运营商交到另一家。

01运营商的网分几层

运营商（ISP，给你接网的公司）的网按覆盖范围分层：越靠近用户，设备越多、每台管的户越少；越往里，设备越少、链路越粗。

层在哪，做什么全流程里
接入网你家到最近的运营商机房：光猫、光纤、OLT（光线路终端），把一户户的线收进来不算跳数
汇聚区县机房里的交换机，把很多台 OLT 的上行并到几根粗光纤上不算跳数
城域网一个城市的核心机房。BRAS 认出你家、发地址；核心路由器收拢全城的流量，交给骨干网第 2、3 台
骨干网省级骨干网连起一个省的各个城市，国家骨干网连起各省第 4 台
互联和出口少数几个城市，和别的运营商、数据中心交换流量，出境（第 09 节）第 5 台
  • BRAS 在城域网的边上。BRAS（宽带接入服务器，新的叫法是 BNG）是你家拨号的另一头：核对账号，发公网地址，按套餐限速。它是去程的第一台、回程的最后一台运营商路由器，细节见 宽带接入。
  • 光猫、OLT、汇聚交换机只转发帧，不查 IP 路由表，不减 TTL，traceroute 里看不到。它们线上的信号见 物理层。
  • 每一层只需要知道下一层的大概。骨干网只知道"这段地址在哪个城市"，城域网知道"在哪台 BRAS 上"，只有 BRAS 知道每个地址给了哪一户。这要求地址按地区成块地分，下一节讲。
  • 用手机流量时，前两层换成基站和移动核心网，见 移动网络。

02地址是怎么分下来的

你家拨号拿到的公网地址（例子里是 203.0.113.7）不是运营商自己编的。全世界的 IP 地址只有一个源头：IANA（互联网号码分配机构）把大块分给 5 个 RIR（地区互联网注册机构：亚太的 APNIC、北美的 ARIN、欧洲中东的 RIPE NCC、拉美的 LACNIC、非洲的 AFRINIC），RIR 再分给会员。会员叫 LIR（本地注册机构），一般是运营商、云厂商，它们再往下分。亚太还有国家一级的 NIR，比如中国大陆的 CNNIC，国内单位可以经它申请。每一级只能在上一级给它的那块里再分。

185.199.108.0/22 这种写法叫前缀，也叫网段：前 22 位固定，后 10 位随便变，共 210 = 1024 个地址。斜杠后的数越小块越大：/24 是 256 个，/16 是 65,536 个，/8 是 16,777,216 个，正好是整个 IPv4（232 个）的 1/256。

IANA：256 个 /8

IANA 的 IPv4 登记表把 256 个 /8 一个个列了出来。129 个分给了 RIR：APNIC 45、ARIN 36、RIPE NCC 35、LACNIC 9、AFRINIC 4。92 个是 RIR 出现之前直接分给机构的，例如 17/8 给了 Apple，19/8 给了 Ford，214/8 和 215/8 给了美国国防部，其中 75 个现在由各 RIR 代管。剩下 35 个保留：0/8、10/8（私有地址）、127/8（本机）、224/8 到 239/8（组播）、240/8 到 255/8（留作将来）。

APNIC 分给了谁

每个 RIR 每天发布一个分配统计文件，一行一块：哪个经济体、什么类型、从哪开始、多大、哪天分的。把 APNIC 2026-11-23 的文件按经济体加起来（IPv6 折成 /32 来数）：

分完以后

2011 年 2 月 3 日，IANA 把最后 5 个 /8 一家一个分了出去：102/8 给 AFRINIC，103/8 给 APNIC，104/8 给 ARIN，179/8 给 LACNIC，185/8 给 RIPE NCC。185.199.108.153 就在最后这批的 185/8 里。

2011 年 4 月 15 日，APNIC 只剩最后一个 /8（103/8），此后每家会员最多从里面领一个 /22（1024 个地址），2019 年起减到 /23。如今 103/8 已分出 93.6%，拆成了 23,113 条记录。RIPE NCC 在 2012 年 9 月 14 日也只剩最后一个 /8，2019 年 11 月 25 日发出了最后一块 /22。

运营商以下没有公开的登记。常见做法是按省、按城市切开，最后切成一台台 BRAS 的地址池，拨号时从池里拿一个发给你，断开时收回，见 宽带接入。地址不够时，家里拿到的是 100.64 开头的内部地址，几百户共用一个公网地址，见 CGNAT。

03查一个地址归谁

每个 RIR 都有一个公开的数据库，记着每块地址给了谁、哪天给的、出了问题找谁。查它有两种协议：

whois（RFC 3912）RDAP（RFC 9082、9083）
怎么问连 TCP 43 端口，发一行文字HTTPS，GET 一个网址

归属地是怎么来的

App 里显示的"IP 归属地"来自商业或开源的地理位置库，是几种数据拼起来的：RIR 登记的国家（只到国家，而且是持有者的国家，按它算 185.199.108.153 在美国）；运营商自己发布的位置表，叫 geofeed（RFC 8805 格式的 CSV，一行一段，例如 RFC 里的 192.0.2.5,US,US-AL,Alabaster,）；从已知地点测延迟；带定位的 App 回传"我在这里，用的是这个 IP"。

所以国家一级大体可靠，城市一级要打折扣：地址池会在城市之间调动（第 11 节）；一个省的手机流量可能从同一处出网（移动网络）；CGNAT 让几百户共用一个地址；任播地址同时在很多城市。

04自治系统和 AS 号

上一节问的是地址归谁，路由问的是另一件事：去这个地址，该交给哪张网。互联网上每张自己做路由决定的网叫一个自治系统（AS，Autonomous System）。运营商、云厂商、大学，各自是一个或几个 AS。每个 AS 有一个号码，叫 AS 号（ASN），也是 IANA 分给 RIR、RIR 再分下去。

AS 号原来是 16 位（0 到 65535），不够用后扩成 32 位（RFC 6793），写法不变，例如 AS131072。64496 到 64511、65536 到 65551 留给文档举例，64512 到 65534、4200000000 到 4294967294 留给内部私用。APNIC 的统计里中国大陆有 6,399 个 AS 号；全球路由表里看得到 80,046 个（第 06 节）。三家主要运营商的几个 AS，在 RIPEstat 里是这样：

  • 一家运营商有好几个 AS。电信的 163 骨干网和 CN2 是两张网，联通、移动也各有一个以上，分工不同。
  • 前缀数说明切得多碎，不说明网多大。AS9808 宣告了 14,108 条，地址只有 AS4134 的三分之一。
  • 有的 AS 主要替别人运流量。AS4809 和 AS58453 自己起源的地址很少，RIS 看到经它们转手的 IPv4 前缀却分别有 89,565 条和 150,339 条。
  • 口径一变，数字差好几倍。连只在小范围看得到的也算上，AS4134 起源的 IPv4 前缀是 2,250 条，不是 726 条。引用这类数字要带上来源、时间和口径。

05BGP：网和网怎么交换路由

AS 之间用 BGP（Border Gateway Protocol，边界网关协议，RFC 4271）互相告诉对方：哪些前缀经我能到。两台路由器之间建一条 TCP 连接（179 端口），叫一个 BGP 会话。不同 AS 之间的叫 eBGP，同一个 AS 内部的叫 iBGP（第 06 节）。

一条宣告（announcement）就是"这个前缀经我能到"，带着几个属性；不再提供这条路时，发一条撤销（withdrawal）：

属性是什么拿来做什么
前缀比如 185.199.108.0/24按最长匹配查表时用的就是它
AS_PATH经过的 AS 列表，每传一次在最左边加上自己的号看到自己的号就丢掉，防止绕圈；比长短
NEXT_HOP下一跳：去这个前缀，包交给哪个地址查出从哪个口发、发给谁
LOCAL_PREF本地优先级，只在一个 AS 内部传按生意关系赋值，见下面

RIS 看到的真实路径

RIPE NCC 的 RIS（Routing Information Service）在世界各地的交换中心放了路由收集器，和几百个网络建 BGP 会话，只收不发。2026-11-22 它对 185.199.108.0/24 收到 342 条路由，挑 4 条（rrc00 在阿姆斯特丹，rrc06 在东京）：

采集点  AS_PATH（左边是采集点的邻居，最右边是起源）
rrc00   3333 9002 54113
rrc00   7018 54113
rrc06   2500 4713 2914 54113
rrc00   4608 4826 54113

54113 是 Fastly；3333 是 RIPE NCC 自己的网，9002 是 RETN；7018 是 AT&T，和 Fastly 直接相连；2500 是 WIDE，4713 是 NTT 的 OCN，2914 是 NTT America；4608 是 APNIC 自己的网，4826 是 Vocus。342 条里，路径长 2 个 AS 的 161 条，3 个的 146 条，4 个的 32 条，5 个的 3 条：九成的路径里，采集点的邻居和起源之间只隔 0 到 1 张网。

选哪条：先看生意，再看长短

同一个前缀常常从几个邻居各收到一条，只能用一条。按固定的顺序比，前一项分出高下就不往下比：

顺序比什么意思
1LOCAL_PREF 大的优先运营商按生意定：客户给的路 > 对等方给的路 > 上游给的路。走客户的路收钱，走对等方的不花钱，走上游的要付钱
2AS_PATH 短的优先经过的网越少越好，不管每张网多大、多远
3eBGP 学来的优先于 iBGP能直接交出去，就不在自己网里绕
4到 NEXT_HOP 的内部距离近的优先从最近的出口把包交出去
5其余MED（邻居希望你从它的哪个入口进）、路由器 ID 等，用来打破平局

第 4 条让每张网都尽早把包交出去，所以去程和回程常常走不同的路。全流程那一页用回来的包数出 6 台路由器，数的是回程。

宣告往哪传也有规矩：从客户学来的路告诉所有人，从对等方和上游学来的只告诉客户，免得替两个不付钱的邻居白运流量。违反它，叫路由泄漏（route leak，RFC 7908）：流量被引到一张本不该承载它的网上，常常把它挤爆。

BGP 本身不检查宣告的人是不是地址的主人。宣告别人的地址叫劫持（hijack）。RIPE NCC 用 RIS 的数据复盘过 2008 年 2 月 24 日这一次（时间是 UTC）：

RPKI：给"谁能宣告"签名

RPKI 让地址的主人签一份 ROA（Route Origin Authorization，RFC 9582）：这个前缀、最长允许拆到多长（maxLength）、由哪个 AS 宣告；RIR 发的证书证明签名的人确实持有这块地址。路由器按 ROA 给每条路由打上 Valid、Invalid 或 NotFound（没有 ROA 覆盖，RFC 6811），开了验证的网络丢掉 Invalid。

$ curl -s 'https://stat.ripe.net/data/rpki-validation/data.json?resource=AS54113&prefix=185.199.108.0/24'
"validating_roas": [                                                     （整理过格式）
  { "origin": "54113", "prefix": "185.199.108.0/24", "validity": "valid",          "max_length": 24 },
  { "origin": "54113", "prefix": "185.199.108.0/22", "validity": "invalid_length", "max_length": 22 } ],
"status": "valid", "validator": "routinator"

两条 ROA 都只授权 AS54113：地址是 GitHub 的，它授权 Fastly 宣告。换几种宣告再问：

06一张网内部怎么找路

BGP 管的是"哪个前缀在哪张网"。一张网内部还要知道：从这台路由器到网里另一台怎么走。这由内部网关协议（IGP）管，常用的是 OSPF（RFC 2328）和 IS-IS。它的表里只有本网路由器自己的地址（环回地址）和它们之间的链路，通常几百到几千条，不是一百多万条。每台路由器把自己有哪些链路、每条开销多少广播给全网，人人手里一张全图，各自算最短路径；断一根线，几百毫秒到几秒内全网就重算完了。BGP 则只听邻居说，变化要等宣告一级级传开。

两张表叠起来用

第 5 台是这张网通往 185.199.108.0/24 的出口。它用 eBGP 学到这条路，再用 iBGP 告诉网里其他路由器，下一跳写成自己的环回地址（示意：192.0.2.5）。第 3 台转发时查两次：

BGP：  185.199.108.0/24   下一跳 192.0.2.5（第 5 台）
IGP：  192.0.2.5/32       从朝第 4 台的口出去，开销 20
合起来：去 185.199.108.153 的包，交给第 4 台

合成的这一行写进转发表（FIB），真正转发时只查它。

iBGP 和路由反射器

iBGP 有一条规矩：从一个 iBGP 邻居学来的路，不再告诉别的 iBGP 邻居，因为同一个 AS 里 AS_PATH 不变，没法靠它防绕圈。结果是 n 台路由器要两两建会话，共 n(n−1)/2 条：100 台是 4,950 条，1,000 台是 499,500 条。路由反射器（RFC 4456）可以把一个客户告诉它的路转告其他客户，每台路由器只要连两台反射器。

07MPLS：骨干网里按标签转发

普通的 IP 转发，每一跳都要在一百多万条里找最长匹配。MPLS（Multiprotocol Label Switching，多协议标签交换，RFC 3031）换了个做法：包进骨干网时，入口判断一次它该走哪条路，在 IP 头前面贴一个 4 字节的标签；中间的路由器只看标签，按自己的表换一个新标签发出去；快出去时再撕掉。

名词意思
FEC转发等价类：要走同一条路的一类包。最常见的是"BGP 下一跳是同一台出口路由器"的包
PE、PPE 在骨干网的边上，负责贴和撕；P 在中间，只换标签。全流程里第 3 台是入口 PE，第 4 台是 P，第 5 台是出口 PE（示意）
  • 标签只在一段线上有意义。24005 是 P1 自己挑的号，只对 PE-A 到 P1 这一段有效。这和家里路由器的 NAT 一个道理：每台设备守着自己的对应表，拿进来的号查出要换上的号（全流程第 6 步）。
  • 标签从下游往上游定。LDP（RFC 5036）让每台路由器告诉邻居"去某台 PE 用哪个标签"，路径跟着 IGP 的最短路走。RSVP-TE（RFC 3209）由入口指定整条路径并预留带宽，用来做流量工程。
  • 倒数第二台就撕掉（PHP，penultimate hop popping）。PE-B 要的是 3，P2 收到 24017 直接弹掉，PE-B 收到的是普通 IP 包，只查一次 IP 路由表。P1、P2 只认识去各台 PE 的标签，不需要全表，也不跑 BGP。

  • 专线的包有两层标签。企业专线常用 MPLS VPN（L3VPN，RFC 4364）：外层标签带包到出口 PE，内层标签告诉出口 PE 这是哪个客户的。同样的包在专线里是 82 字节，标签栈是 05 dd 10 3d 05 e2 61 3d：外层 24017 的 S 是 0，内层 24102 的 S 是 1。每个客户的路由在 PE 上单放一张表，几家客户都用 10.0.0.0/8 也不会打架。
  • 这种 VPN 和 VPN 那一页讲的不是一回事。那种是在你的设备上给 IP 包套一层加密的头；这种是运营商在自己网里用标签把客户分开，不加密。

运营商用 MPLS，除了让中间的路由器不装全表、做专线，还用来做流量工程（最短路挤满了，用 RSVP-TE 把一部分流量指到有空余的路上）和快速重路由（提前算好备用的标签路径，断线时前一台直接改贴）。新一点的做法是段路由（Segment Routing，RFC 8402）：入口把整条路写成一串"段"放进包里，中间的路由器不记状态，也不用 LDP、RSVP-TE。写成标签栈的叫 SR-MPLS（RFC 8660），一个节点在全网用同一个标签值，不再一跳一换；写成 IPv6 地址、放进扩展头的叫 SRv6（RFC 8754、8986）。

08每一跳都换一个新帧

骨干网里多是一根光纤直连两台路由器，线上只有这两台。给它编地址用最小的网段：/30 有 4 个地址，去掉网络号和广播只剩 2 个能用；/31 也是 2 个，RFC 3021 规定点对点链路两头都能用，省一半；IPv6 用 /127（RFC 6164）。按 /31 把第 2 台到第 6 台之间的几段写出来（示意），MAC 和 TTL 与全流程那一页一致：

好几条一样好的路：ECMP

两台路由器之间常有几条开销相同的路：两根并行的光纤，或者经过两台不同的 P。路由器把它们都放进表里分摊流量，叫等价多路径（ECMP）。分摊按流不按包：把源地址、目的地址、协议、源端口、目的端口算一个哈希，按结果选路。同一个连接的每个包算出来都一样，全程走一条路，就不会乱序；乱序会让 TCP 以为丢了包，见 TCP 拥塞控制。

  • traceroute 每次走的路可能不同。经典的 traceroute 每发一个探测包，目的端口加 1（从 33434 起），每个 TTL 发 3 个。端口一变哈希就变：按上面的示意算法，33434 到 33439 落在 A、A、B、B、B、B。所以 ECMP 之后的一行可能出现两个地址，两次的结果也可能不同。macOS 的 traceroute -e 固定目的端口；Paris traceroute 专门解决这个问题。

09运营商之间怎么连

没有哪张网能直接连到所有的网。两张网之间，大体是两种关系：

转接（transit）对等（peering）
钱客户付给上游，一般按带宽通常互不结算
交换的路由上游把全世界的路由给客户，再把客户的路由告诉全世界只交换双方自己的和各自客户的
在哪连同一栋楼里两台路由器直接拉一根线；或者都接到互联网交换中心（IXP）的交换机上，一次接入，和很多家互联。RIS 的收集器也放在这些地方，比如 rrc03 在阿姆斯特丹的 AMS-IX

国内几家怎么互通

国内各家骨干网之间只在指定的地点交换流量：国家级互联网骨干直联点。工信部 2013 年 10 月的通知说，当时八家骨干网单位都通过北京、上海、广州三地的直联点和交换中心互联，网间互联总带宽 1,492 Gbps，并决定在成都、武汉、西安、沈阳、南京、重庆、郑州增设七个。此后又加了杭州、贵阳·贵安、福州（2017 年），南宁、呼和浩特、太原、济南、青岛（2021 年获批），哈尔滨（2022 年开通）。

直联点开在哪，决定跨网要绕多远。黑龙江省通信管理局 2022 年 11 月报道，哈尔滨直联点开通后，省内本地网间时延下降超过 90%，跨省网间时延下降近 20%，丢包率下降超过 50%。在这之前，同在黑龙江的两家用户互访，流量要先出省，交接完再回来。

所以"跨网慢"（比如电信用户访问联通机房里的服务器）有三个来源：交接只能在直联点，要绕路；网间带宽要结算（2013 年那份通知里，交换中心的结算价从 100 万元每 G 每月降到 60 万元），扩容有成本，高峰期先在这里排队、丢包；去程和回程各自就近交出（第 05 节），可能走的是两个不同的直联点。

从部署方看：多线机房

如果你要部署一个视频或直播服务，用户分在三家运营商，常见的做法：

做法用户怎么连好处代价

每家运营商各放一组服务器DNS 按用户的运营商给地址不跨网几套机器；DNS 认错运营商就跨网，比如用户用了别处的公共 DNS（DNS 的调度）

CDN节点放进各家运营商的网里（第 10 节）离用户近按流量付费；冷门内容回源时仍可能跨网

播放器拉的是一个个分片，起播和卡顿取决于每个分片请求的往返时间和带宽（流媒体协议）。跨网多绕的几十毫秒，乘上起播前的几次往返，就是用户能感觉到的差别。

出境

去境外的流量要经过国际出入口：运营商在少数几个城市设国际出口，从那里接上跨境的陆缆和海底光缆，再和境外的运营商对等或者买转接。出口的容量和走哪条光缆，决定了访问境外网站的延迟和高峰期的拥塞。三家运营商各有做国际业务的网络，比如中国移动国际（AS58453），RIS 看到它有 711 个邻居 AS，是第 04 节表里最多的。

11地址会被收回和转手

地址分下去以后并不固定，在三个层面上流动：

  • 一户和地址，每次拨号都可能变。断线重拨，BRAS 可能从池里给你另一个地址（宽带接入）。
  • 地址池和城市，按需调整。某个城市的用户多了，运营商从别处的池里挪一块过去。这块地址的"归属地"跟着变了，地理位置库要过一阵才跟上。
  • 地址和持有者，买卖时变。IPv4 分完以后，地址可以在单位之间转让，由 RIR 登记过户。

旧地址带着旧名声

  • 黑名单。上一个使用者发过垃圾邮件、扫过端口，地址可能还在各种拦截名单上：新主人的邮件进垃圾箱，访问某些网站要过验证。
  • 归属地。地理位置库里还是上一个主人的国家和城市，按地区授权内容的服务会认错。
  • 路由登记。旧的 ROA 和 IRR 记录没删，新主人宣告时可能被判 Invalid，或者被上游按 IRR 过滤掉。

对 App 来说，这一节的结论是：用户的 IP 不是身份。它隔天就可能换，可能和几百户共用（CGNAT），上个月可能还属于别人。按 IP 限流、封禁，会误伤一大片。

IPv6：按块分

IPv6 有 2128 个地址，分法反过来了：给得很大，按块数算，不按个数算。

一级常见大小实例和算术
运营商/32 起，大运营商更大RDAP 里，中国电信是 240e::/18，中国移动是 2409:8000::/20，中国联通是 2408:8000::/20。一个 /20 是 212 = 4,096 个 /32，一个 /18 是 16,384 个；中国大陆合计 68,539 个（第 02 节）
一户/56 到 /60一个 /32 能分出 224 = 16,777,216 个 /56，或者 228 = 268,435,456 个 /60；一个 /20 能分出 236，约 687 亿个 /56
局域网/64一个 /56 能分 256 个 /64，一个 /60 能分 16 个；每个 /64 里有 264 个地址

局域网固定用 /64，是因为设备自己生成地址（SLAAC）要用后 64 位，Android 手机拿 IPv6 地址靠的就是它。家里的路由器从运营商领一整段，再切成 /64 发给各个网段，见 宽带接入。地址给得这么宽，就用不着 NAT；也因为宽，按单个 IPv6 地址封禁基本没用，要按 /64 或 /56 封。

12自己能查到什么

这一页的数据都来自公开接口，不需要账号：

# 这个地址归谁：RDAP，返回 JSON。rdap.org 按 IANA 的引导文件跳到对应的 RIR
curl -s https://rdap.org/ip/185.199.108.153
# 老的 whois，纯文本
whois -h whois.ripe.net 185.199.108.153
# 这个 AS 是谁、宣告了多少（RIPEstat 的数据接口）
curl -s 'https://stat.ripe.net/data/routing-status/data.json?resource=AS4134'
# 谁在宣告这个地址、各地看到的路径、RPKI 结果
curl -s 'https://stat.ripe.net/data/prefix-overview/data.json?resource=185.199.108.153'
curl -s 'https://stat.ripe.net/data/bgp-state/data.json?resource=185.199.108.0/24'
curl -s 'https://stat.ripe.net/data/rpki-validation/data.json?resource=AS54113&prefix=185.199.108.0/24'

网页上看：stat.ripe.net 是这些接口的网页版，能看历史变化；bgp.he.net 列出一个 AS 宣告了哪些前缀、和哪些 AS 相连；bgp.potaroo.net 记录全球路由表的大小。很多运营商和交换中心还开放了 Looking Glass：在网页上对它们的路由器做只读查询（看路由、ping、traceroute），等于从对方的网里往外看。

读 traceroute

traceroute 能列出包沿途经过的路由器。下面是一段示意输出，不是实测，地址按这一页的设定：

$ traceroute -n 185.199.108.153
 1  192.168.1.1       1.1 ms   0.9 ms   1.0 ms      家里的路由器
 2  203.0.113.1       4.0 ms   3.8 ms   4.1 ms      BRAS
 3  198.51.100.1      5.0 ms   5.2 ms   4.9 ms      城域网核心，入口 PE
 4  * * *                                           P 路由器不回
 5  198.51.100.5      9.6 ms   198.51.100.13  10.1 ms   9.7 ms
 6  198.51.100.7     10.3 ms  10.2 ms  10.4 ms      机房路由器
 7  185.199.108.153  10.5 ms  10.4 ms  10.6 ms
  • 一行 * * * 不等于丢包。traceroute 等 5 秒没收到回应就打一个 *（man 手册）。有的路由器不回 TTL 超时的通知，或者限制了每秒回几个。后面的跳正常回应，说明包是过去了的。
  • 中间某一跳延迟特别高、后面又正常，是那台路由器把生成通知排在了低优先级，不是路上慢。以最后一跳为准。
  • 一行出现两个地址（第 5 行），是 ECMP：三个探测包分到了两台路由器上（第 08 节）。
  • 经过 MPLS 的几跳，延迟常常和出口那一跳差不多。P 路由器没有回程的路由，会把通知顺着标签路径送到出口 PE，再由出口 PE 发回来（RFC 3032）。Linux 上的 mtr -e 能显示路由器附在通知里的标签（RFC 4950）。
  • 开头是 100.64 到 100.127，或者 10.、172.16 到 172.31、192.168 的地址，是运营商内部的链路用了不对外的地址；第 2 跳附近出现 100.64 开头的，你可能在 CGNAT 后面（CGNAT）。
  • 反向解析出来的名字常带着城市。不加 -n 时，traceroute 会把地址反查成名字，运营商常把设备类型、编号和城市写进去，比如虚构的 ae2.cr01.sha1.example.net：接口 ae2、核心路由器 01、上海第 1 个机房。写法各家自定，可能过时，只能参考。

国内的 traceroute 里常见几段骨干网的地址，RDAP 里登记的是：202.97.0.0/19 为 CHINANET-BB（中国电信骨干网），59.43.0.0/16 为 CN2-BB，219.158.0.0/19 为 ChinaUnicom-BACKBONE，221.176.0.0/13 为 CMNET（中国移动）。开头一样不代表是同一家：202.97.192.0/18 登记的是 UNICOM-HL（联通黑龙江）。拿不准就查 RDAP。

13常见坑

现象原因处理
IP 归属地显示在别的城市，甚至别的省地址池在城市之间调配；手机流量从省里少数几处出网；CGNAT；地理位置库更新慢城市只当参考；真要位置，用系统的定位权限
185.199.108.153 的归属地是美国，延迟却很低登记的国家是持有者的国家；任播地址在很多地方同时存在不要用登记的国家判断服务器在哪
电信用户访问联通机房很慢，晚上更慢跨网：只能在直联点交接，可能要绕路，交接口高峰期拥塞先看用户和服务器是不是同一家；服务端用 BGP 多线、分运营商部署或 CDN
traceroute 某一行全是 *那台路由器不回 TTL 超时通知，或者限速看后面几跳，后面正常就不是丢包
两次 traceroute 走的路不一样，或者一行出现两个地址ECMP 按流哈希，每个探测包的端口不同；路由也会变macOS 用 traceroute -e 固定端口，或者用 Paris traceroute
traceroute 里出现 100.64 或 10. 开头的地址运营商内部链路用不对外的地址；或者你在 CGNAT 后面正常，不是故障。是不是 CGNAT 见 CGNAT
同一个地址，在不同地方 ping 的延迟差很多任播：每个人连到的是自己路由上最近的那个节点不要用一个地方的延迟推断服务器在哪
换了新服务器地址，邮件进垃圾箱、部分网站要验证地址继承了上一个使用者的名声上线前查黑名单和地理位置库，必要时申请移除
新宣告的前缀在一部分网络里不通没有 ROA 或者和宣告不符，被判 Invalid；IRR 里没有 route 记录，被上游过滤先建 ROA 和 IRR 记录，再宣告
按 IP 限流误伤一大片；同一个用户隔天 IP 就变了CGNAT 让几百户共用一个地址；重新拨号、地址池调配都会换地址按账号或设备限流，不要把 IP 当身份

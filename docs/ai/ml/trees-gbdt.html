决策树和 GBDT：另一类常用算法

逻辑回归和神经网络做预测，底子都是加权求和：特征乘上权重，再加起来。决策树换了一种做法：问一串是非题，走到哪个叶子，就报那个叶子里训练样本的正样本比例。把很多棵小树一棵接一棵地加起来，就是 GBDT，表格数据上最常用的模型之一。这一页用同一份音乐推荐数据，从一棵树讲到 103 棵树，再看一条样本的分数是怎么一棵一棵加出来的。

数据是脚本按固定随机种子生成的示意数据：音乐 App 首页推荐的 3000 次曝光，一次曝光是给一位用户展示一首歌，点开并播放超过 30 秒算正样本。第 1–20 天训练（2000 条），21–24 天验证（400 条），25–30 天测试（600 条）。GBDT 的配方、曲线、前三棵树、重要度和各模型的指标来自这几页共用的参考脚本；单棵树、森林、学习率对比和样本 2462 的逐棵累加是另外算的，配方见各节和页尾。它是加权求和之外的另一条路。

01一串是非题

逻辑回归预测时，把每个特征乘上一个权重，加起来，再用 sigmoid 压成 0 到 1 之间的概率（梯度下降）。决策树（decision tree）不做乘法，它问问题："这位用户最近 7 天听这个曲风超过 3 次了吗？"答"是"往左走，答"否"往右走，下一个问题取决于上一个的答案。问到头，就报那里存着的一个数。

每个问题叫一个节点（node），只看一列，形式都是"这一列 ≤ 某个数吗"，那个数叫切点（threshold）。问题把样本分成两份，叫切分（split）。不再往下问的地方叫叶子（leaf），分类树的叶子存的是：训练时落到这里的样本里，正样本占多少。从最上面的根节点到叶子最多问几次，叫深度（depth），深度 3 最多 8 个叶子。预测就是从根往下走到叶子，只有比较，没有乘法。

用真实数据建一棵

用第 1–20 天的 2000 条训练样本，和其他几页一样的 15 个特征（特征和样本），只是保留原始单位，不做缩放。图里出现的是四列：affinity 是偏好，这位用户最近 7 天听这个曲风的次数，这份数据里是 0 到 17 的整数；heat 是歌曲热度，0 到 1；follow 是有没有关注这首歌的歌手，0 或 1；song_min 是歌曲时长，2 到 6 分钟。另外还有曝光的钟点 hour、是否晚上 night（18 点到次日 2 点前）、是否新用户，以及网络和曲风拆成的 0/1 列。

建树的规则是 CART 的做法，下一节细讲：每个节点把 15 列的所有切点都试一遍，挑让 Gini 不纯度降得最多的那个；最多 3 层；每个叶子至少留 50 个样本。结果是这样：

图上能直接读出几条规律：

  • 第一个问题问的是 affinity。最近听过 4 次以上的一边，正样本比例是 33.2%，另一边是 18.2%。
  • 两边接下来问的不一样。听得少的一边问热度，听得多的一边问是否关注歌手。后面的问题只在前面的答案成立时才问，所以一条路径就是几个条件的"并且"。
  • 8 个叶子相差很大。最好的是"听过 8 次以上、关注了歌手"：51 个样本里 31 个正样本，60.8%。最差的是"听过不到 4 次、热度 ≤ 0.738、没关注"：1049 个里 147 个，14.0%。

这棵树在验证集上的 AUC 是 0.6294，测试集 0.6748。AUC 的意思是：随便抽一个正样本和一个负样本，模型给正样本的分数更高的概率；0.5 等于瞎猜，1 是全对（评估）。同样的数据，逻辑回归是 0.6438 和 0.7175。一棵 3 层的树比不过它，但它只有 7 个问题和 8 个叶子。

02切在哪：不纯度

上一节那棵树用的是 CART（Classification and Regression Trees，Breiman 等人 1984 年的书）的做法。规则只有一条，从根开始反复做：在当前节点上，把每一列的每一个可能的切点都试一遍，挑分得最"干净"的那个；切出来的两份各自再来一遍，直到该停为止。每一步只挑眼前最好的、不管后面，这种做法叫贪心（greedy）。

"干净"用不纯度（impurity）来量，这里用的是 Gini 不纯度。节点里正样本的比例是 p：

Gini = 1 − p² − (1 − p)² = 2p(1 − p)

它的意思是：从这个节点里随手抽两个样本，两个标签不一样的概率。全是正样本或全是负样本时是 0，一半一半时最大，是 0.5。一次切分好不好，看切完以后两边的 Gini 按样本数加权，比切之前降了多少。

根节点上的一次切分

切之前  n = 2000  正样本 454  p = 0.2270  Gini = 2 × 0.2270 × 0.7730 = 0.35094
左边　  n = 1400  正样本 255  p = 0.1821  Gini = 0.29793     affinity ≤ 3.5
右边　  n =  600  正样本 199  p = 0.3317  Gini = 0.44333     affinity > 3.5
切之后  0.7 × 0.29793 + 0.3 × 0.44333 = 0.20855 + 0.13300 = 0.34155
下降　  0.35094 − 0.34155 = 0.00939

右边的 Gini 比切之前还大，因为它的比例离 50% 更近了。但右边只占 30%，占 70% 的左边变干净了，加权之后整体是降的。

切点取相邻两个取值的中点。affinity 是整数，3 和 4 之间取 3.5，"≤ 3.5"就是"听过 0 到 3 次"。根节点上 15 列一共有 398 个候选切点，去掉会让某一边不到 50 个样本的，还剩 378 个，每个都要像上面这样算一遍。affinity 的每个切点算出来是这样：

  • 树不需要缩放特征。切分只看大小顺序。把 affinity 除以 30，切点从 3.5 变成 0.1167，分出来的还是同一批样本。参考脚本的 GBDT 用的就是除过的特征，后面会换算回原始单位。
  • 换一种不纯度，结论差不多。另一种常用的是信息熵 −p·ln p − (1 − p)·ln(1 − p)，它正好是"整个节点都报 p"时的平均对数损失（每条样本取 −ln（模型给真实标签的概率），再平均，见梯度下降），而 Gini 正好是这时平方误差的 2 倍。用熵建同样的树，根切在 affinity ≤ 2.5，前两层用的列不变。Gini 不用算对数，CART 默认用它。
  • 什么时候停：到了最大深度；节点里只剩一类；或者每一种切法都会让某一边少于规定的样本数。

03组合条件不用手写

生成这份数据时埋了一条规律：晚上（18 点到次日 2 点前）长歌（4 分钟及以上）更容易被听完，白天正好反过来。全部 3000 条按这两个条件分成四格，正样本比例是：白天短歌 34.7%（784 条），白天长歌 12.0%（825 条），晚上短歌 12.0%（675 条），晚上长歌 31.6%（716 条）。

两个条件一致的两格高，不一致的两格低，这种形状叫异或（XOR）。只看一个条件几乎看不出差别：训练集里白天 24.1%，晚上 21.0%。

加权求和排不出这四格：两条对角线上的分数加起来永远相等，证明见神经网络。只给逻辑回归 night 和 long（是否 4 分钟及以上）两列 0/1，和只用这两列的深度 2 的树比一比：

格训练集实际逻辑回归，只用这两列深度 2 的树，只用这两列
白天、短歌36.2%26.4%36.2%
白天、长歌11.9%21.8%11.9%
晚上、短歌11.9%23.1%11.9%
晚上、长歌30.6%18.9%30.6%

逻辑回归只学到"晚上低一点、长歌低一点"，四格的高低整个错了。深度 2 的树先问是不是长歌，再在两边各问一次是不是晚上，四个叶子正好是四格，叶子值就是每格的比例。一条路径本身就是"并且"：长歌并且晚上。不用事先告诉树哪两列要组合。

逻辑回归要做到同样的事，得人工加一列交叉特征：night 和 long 相同时为 1。参考脚本里"逻辑回归 + 1 个交叉特征"那一组就是这样，测试 AUC 从 0.7175 升到 0.7715（交叉特征）。

能表示，不等于能找到

上面那棵树喂的是现成的 night 和 long。只给原始的 hour 和 song_min 两列、深度还是 2，贪心的结果是：根切 song_min ≤ 5.75（特别长的歌比例低一些，14.3%），第二层切 hour ≤ 1.5。18 点和 4 分钟这两条线一条也没找到，训练集 AUC 只有 0.53。

原因在第 02 节的表里：单独按 night 切，Gini 只降 0.00047，是 affinity 那一刀的二十分之一。异或要连切两刀才见效，第一刀几乎没有好处，而贪心一次只看一刀。第 06 节的 GBDT 直到第 41 棵树才把它找出来。

04深树会背答案

叶子的值是数出来的：落进叶子的训练样本里有几个正样本。样本越少，这个比例越靠运气。第 01 节那棵树的叶子拿到测试集上再数一遍：1049 个样本的叶子，训练集 14.0%，测试集 13.3%；100 个样本的叶子，训练集 28.0%，测试集 42.9%（只有 28 条测试样本落进去）。

剪枝（pruning）用的是 CART 的代价复杂度剪枝：每个叶子记一笔罚分 α，α 从 0 慢慢加大，每次剪掉"少一个叶子、不纯度涨得最少"的子树，得到一串越来越小的树（从 481 个叶子到只剩根，共 149 棵），再用验证集挑。设成多少都用验证集比，测试集只在最后看一次。

单棵树还有一个毛病：不稳。训练数据稍有变化，根上的切点就可能换掉，下面整棵树跟着变。第 02 节换一种不纯度，根就从 3.5 换成了 2.5。限制治不了不稳，下一节的办法是种很多棵。

05Bagging 和随机森林

长满的树每一棵都背了一份噪声。训练数据不同，背下的噪声也不同，规律却是同一份。把很多棵这样的树平均起来，噪声互相抵消，规律留下。这是 Breiman 在 1996 年提出的 Bagging（bootstrap aggregating）：

  1. 从 2000 条训练样本里有放回地抽 2000 次，得到一份新的训练集。有的样本被抽到好几次，有的一次也没有，平均只有 63.2% 的样本会出现。这叫自助采样（bootstrap）。
  2. 用这份数据训一棵长满的树。
  3. 重复 100 次，得到 100 棵树。预测时每棵树各报一个叶子比例，取平均。

Breiman 在 2001 年又加了一条，就是随机森林（random forest）：每次切分不看全部 15 列，只从随机挑出的几列里选，分类问题常取特征数的平方根，这里是 4 列。如果每棵树都在根上切 affinity，100 棵树会犯差不多的错，平均也抵消不掉；随机挑列让树和树更不一样，平均的效果更好。

在这份数据上实际跑了一遍，随机种子固定：

  • 平均很管用。同样是长满的树，100 棵平均以后测试 AUC 从 0.5448 到 0.6888，对数损失从 9.4 回到 0.51：单棵树报 0% 的地方，100 棵里总有几棵报的不是 0。棵数从 1、10、50 加到 100，随机森林的测试 AUC 是 0.6037、0.6258、0.6828、0.6888。
  • 多加树不会让森林过拟合。Breiman 2001 年的论文证明了误差随棵数增加会收敛，多出来的树只是让平均更稳，代价是慢。
  • 每棵树都有约 36.8% 的样本没见过，可以拿它们给这棵树当验证集，叫袋外（out-of-bag）估计，不用另外留数据。
  • 在这份数据上，森林最好也就和逻辑回归（0.7175）打平。它的长处是不怎么挑参数，各棵树可以并行训练。下一节换了一个思路。

06梯度提升：下一棵修前面的错

森林里的树各训各的，最后取平均。提升（boosting）反过来：树一棵接一棵地训，每一棵都去修前面所有树加起来还没做对的部分。最后的分数是所有树的输出加起来：

F = F0 + η × f1 + η × f2 + … + η × f103
p = sigmoid(F) = 1 / (1 + e^(−F))

F 是分数，和逻辑回归加权求和得到的那个数是同一种东西，叫对数几率（logit），等于 ln(p / (1 − p))。F0 是起点；fk 是样本在第 k 棵树落进的叶子的值，不是概率，是往分数上加的量，可以是负数；η 是学习率，每棵树的输出先乘上它再加。这套做法叫梯度提升（gradient boosting），Friedman 2001 年的论文系统地写了出来；每个 fk 都是决策树时，叫 GBDT（Gradient Boosting Decision Tree）。

起点

一棵树都还没有的时候，每个样本都报训练集的正样本比例 22.7%，对应的分数是 F0 = ln(454 / 1546) = −1.2253。

每棵树拟合梯度

对数损失对一个样本的分数 F 求导，结果很简单，和逻辑回归训练时用的是同一个式子（梯度下降，总览第 4 站）：

g = p − y          一阶导数，就是梯度：预测减答案
h = p · (1 − p)    二阶导数：损失曲线在这里有多弯

第一棵树之前，所有样本的 p 都是 0.227：正样本的 g 是 −0.773，负样本是 +0.227，h 都是 0.1755。g 为负，说明分数该往上推。新的一棵树要做的，是把 g 相近的样本分进同一个叶子，再给每个叶子定一个值，把里面样本的分数一起往 g 的反方向推。

叶子值：牛顿步

一个叶子里，G 是所有样本的 g 之和，H 是 h 之和。叶子值取

w = −G / (H + λ)

只有梯度，知道往哪走，不知道走多远。除以曲率 H，就是牛顿法的一步：如果损失是一条抛物线，这一步正好落在最低点。λ 是正则项，这里是 1，样本少、H 很小的时候不让步子太大。第 1 棵树的第 4 个叶子：

叶子：affinity > 3.5 并且 follow = 1，108 个样本，54 个正样本
G = 108 × 0.227 − 54      = −29.48
H = 108 × 0.1755          =  18.95
w = 29.48 / (18.95 + 1)   =   1.478
这一棵给这 108 个样本的分数加 0.05 × 1.478 = 0.074，概率从 22.7% 变成 24.0%

这个叶子的实际比例是 50%。从 22.7% 一步走到 50%，分数要加 1.225；牛顿步算出 1.478，乘上学习率 0.05，只走了 0.074。剩下的留给后面的树。

切分：同样是贪心，换一个量法

挑切分的办法和第 02 节一样，试遍候选切点，只是"切完好多少"换成了增益：

增益 = ½ × [ G_L² / (H_L + λ) + G_R² / (H_R + λ) − G² / (H + λ) ]

第 1 棵树的根切在 affinity ≤ 3.5：左边 G = 62.8、H = 245.66，右边 G = −62.8、H = 105.28，切之前 G = 0（起点就是平均值，梯度正负正好抵消）。增益 = ½ × (62.8² / 246.66 + 62.8² / 106.28) = 26.55，所有候选里最大。

参考脚本的配方：每棵树深度 2，学习率 0.05，最多 300 棵，λ = 1，每个叶子至少 20 个样本，连续的列只在 32 个分位点上找切点。它的特征是除过的（affinity / 30、hour / 23、(song_min − 2) / 4），下面的切点都已换算回原始单位，比如 0.1167 × 30 = 3.5。

07学习率和棵数

每多一棵树，训练集损失都会再降一点，它永远在降。验证集前面跟着降，到第 103 棵最低（0.4694），之后慢慢回升：后面的树开始拟合训练集里的噪声。按验证集损失挑棵数，叫早停（early stopping），参考模型就停在 103 棵。

测试集是挑完以后才看的。103 棵时它是 0.4847，训到 300 棵还在慢慢降，到 0.4779。验证集 400 条、测试集 600 条，在一份上挑出的最好点，换一份不一定还是最好。

09哪些特征用得最多

每次切分都有一个增益。把 103 棵树里用到某一列的所有切分的增益加起来，就是这一列的增益重要度（gain importance）。数据是生成的，可以拿生成时的规律对照，右边一列是这一项在对数几率上加减多少：

  • 规律里没有的列也分到了一点。g_古典 是 16.9：比如第 13 棵在关注了歌手的 237 个样本里，又按是不是古典切了一刀，切出一个 30 个样本的叶子。2000 条数据里，排在后面的重要度多半是噪声。

11XGBoost、LightGBM、CatBoost

本页的 GBDT 是参考脚本里三十来行 JS。实际工作中用的是三个开源库，核心都是第 06 节的算法，各自加了不同的东西：

库出处加了什么
XGBoost陈天奇、Carlos Guestrin，2016 年 KDD 论文把正则直接写进目标函数：叶子值的 L2（本页的 λ），每多一个叶子再罚 γ；用一阶、二阶导数算叶子值和增益，就是第 06 节那两个式子；每个节点给缺失值学一个默认方向；按分位数近似找切点，多线程并行，数据放不下内存时分块读
LightGBM微软，2017 年 NIPS 论文先把每列分进最多 255 个桶（直方图），只在桶的边界上找切点；按叶子生长：每次挑全树增益最大的那个叶子切，用叶子数（默认 31）控制大小，不再一层一层切满；GOSS：梯度小的样本只抽一部分来算；EFB：把从不同时非零的稀疏列捆成一列
CatBoostYandex，2018 年 NeurIPS 论文类别特征换成"有序目标统计"：把样本随机排个序，每个样本只用排在它前面的样本算这个类别的平均标签，避免把自己的标签漏进特征；有序提升；对称树：同一层的节点问同一个问题，深度 d 的树就是一张 2d 格的表，预测时把 d 个比较结果拼成下标直接查
  • 参考脚本的几个选择就来自它们。λ = 1 是 XGBoost 的默认值；叶子至少 20 个样本是 LightGBM 的默认值；只在 32 个分位点上找切点，是直方图做法的简化版。
  • 默认参数差别不小。XGBoost 默认深度 6、学习率 0.3；LightGBM 默认最多 31 个叶子、学习率 0.1；CatBoost 默认深度 6。本页的数据只有 2000 条，用的是更小的树和学习率。

12什么时候用树

数据常用原因
表格：每一列有自己的含义（次数、比例、时长、类别），几千到几千万行GBDT不用标准化，不怕各列单位、分布不一样；组合自己找；要调的参数少，训练快
图像、音频神经网络单个像素、单个采样点没有意义，有用的是一片相邻的值组成的形状。树一次只比较一列，拼不出形状
文本神经网络意思在词的顺序和上下文里，见大模型
海量 ID：几百万用户、几千万首歌神经网络ID 的大小没有意义。拆成 0/1 列就是几百万列，每列只有很少的样本是 1，切一刀分不出多少样本。神经网络给每个 ID 学一个向量（embedding），见点击率预估

表格数据上，GBDT 长期是最强的一类模型。2022 年 NeurIPS 上 Grinsztajn 等人的基准论文《Why do tree-based models still outperform deep learning on tabular data?》专门比过：在中等规模的表格数据上，树模型整体领先。近几年也有专为表格设计的神经网络在一些基准上追平甚至超过它，但 GBDT 仍是最常用的起点。本页的结果也一样：GBDT 0.7499，神经网络 0.731。

GBDT + 逻辑回归

推荐和广告里有一种经典组合：先训一个 GBDT，不用它的分数，而是记下每个样本在每棵树落进了哪个叶子，把"第几棵树的第几个叶子"做成 0/1 特征，再交给逻辑回归。Facebook 2014 年的论文《Practical Lessons from Predicting Clicks on Ads at Facebook》描述了这种做法，来龙去脉见模型的演进。

拿本页的模型说：103 棵树、每棵 4 个叶子，一共 412 列。样本 2462 在第 1 棵落进第 3 个叶子，在第 41 棵落进第 4 个，412 列里正好 103 列是 1。每个叶子是两个条件的"并且"，所以这 412 列是树替你做好的组合特征。GBDT 自己的预测其实就是这 412 列的加权和，权重是 0.05 × 叶子值；换成逻辑回归，是把这些权重拿去重新学，还能和别的特征放在一起训。

13预测一次的代价

学完的模型就是一堆数（总览第 8 站）。树模型的数是：每个问题比哪一列、切点是多少，每个叶子的值。

模型预测一次要做的模型里的数
逻辑回归15 次乘加，1 次 sigmoid16 个
神经网络 15 → 16 → 8 → 115×16 + 16×8 + 8 = 376 次乘加，24 次 ReLU，1 次 sigmoid401 个
深度 3 的树3 次比较7 个问题，8 个叶子值
GBDT，103 棵深度 2103 × 2 = 206 次比较，103 次加法，1 次 sigmoid309 个问题（各一个列号、一个切点），412 个叶子值，加上起点，一共 1031 个数，按 4 字节存约 4 KB
  • 比较次数 = 棵数 × 深度，和有多少列无关。1000 棵深度 6 的树，预测一次 6000 次比较；每棵 63 个问题、64 个叶子，一共 19 万个数，按 4 字节约 760 KB。
  • 比较意味着跳转。下一步读哪个节点取决于这一步的结果，不像矩阵乘法那样整齐，CPU 的向量指令帮不上多少忙。
  • 真正花时间的常常是算特征。affinity 要去数这位用户最近 7 天的播放记录，而且必须和训练时同一个算法（总览第 10 站）。

本页的 103 棵树都是满的深度 2，可以直接按数组存，在 Android 上用几行 Kotlin 预测：

import kotlin.math.exp

// 每棵树 3 个问题（根、左、右）、4 个叶子，一棵接一棵连续存
class Gbdt(
    private val feature: IntArray,      // 103 × 3：这个问题看第几列
    private val threshold: FloatArray,  // 103 × 3：切点，原始单位
    private val leaf: FloatArray,       // 103 × 4：叶子值，已经乘过 0.05
    private val base: Float = -1.2253f, // 起点 F0
) {
    fun predict(x: FloatArray): Float {
        var f = base
        for (t in 0 until leaf.size / 4) {
            val q = t * 3
            val right = x[feature[q]] > threshold[q]    // 第一问，答"否"往右
            val q2 = q + if (right) 2 else 1            // 第二问是哪个节点
            val right2 = x[feature[q2]] > threshold[q2]
            f += leaf[t * 4 + (if (right) 2 else 0) + (if (right2) 1 else 0)]
        }
        return 1f / (1f + exp(-f))
    }
}

没有任何依赖。切点要和喂进去的特征同一个单位：参考脚本里的切点是除过的（0.1167），这里换算成原始单位存（3.5），就要喂原始的 affinity。

14常见坑

现象原因处理
训练 AUC 接近 1，验证集只有 0.57树长满了，平均 4 个样本一个叶子，背下的是噪声限深度、限叶子样本数或剪枝，用验证集挑；或者换成森林、GBDT
验证集对数损失突然变成好几只有几个样本的叶子报 0% 或 100%，错一条就记 27.6叶子至少留几十个样本；要输出概率时用森林的平均或 GBDT
GBDT 训练损失一直降，验证集和线上变差树太多，后面的树在拟合噪声按验证集早停；学习率小一些，曲线更平，停早停晚影响都小
把增益重要度读成"这个特征作用有多大"组合带来的增益记在单列头上；相关的列互相分；连续的列候选切点多，更容易被选中在验证集上用置换重要度复核；想知道因果要做实验
取值超出训练范围以后，预测不再变化树是分段常数，最右边的叶子一直管到无穷大。这份数据里 affinity 最大是 17，听 30 次和听 17 次得分一样训练数据要覆盖线上的取值范围；需要外推的部分交给线性模型

自己写的预测代码，分数整体偏了漏了起点 F0；叶子值没乘学习率，或者导出时已经乘过又乘了一遍；忘了过 sigmoid拿几条样本和训练库的输出逐棵对
缺失值走错了分支NaN 和任何数比较都是 false，x > t 不成立就进了左边。XGBoost、LightGBM 训练时给每个节点定了缺失值走哪边按模型文件里记的方向走；或者线上线下用同一个填充值
用户 ID、歌曲 ID 直接当数值列ID 的大小没有远近，id ≤ 123.5 是在记名单，换一批用户就失效换成统计特征，比如这首歌过去的完播率；或者交给神经网络学 embedding

所有数字来自同一份示意数据（3000 行，脚本按固定随机种子生成；第 1–20 天训练，21–24 天验证，25–30 天测试）。GBDT 的配方、损失曲线、前三棵树、增益重要度，以及逻辑回归、神经网络、交叉特征各组的指标，取自这几页共用的参考脚本。样本 2462 的逐棵累加、第 41 棵树、按路径分组的贡献、四格的平均预测、学习率 0.3 和 1.0 两组、GBDT 加交叉特征一组，是把参考脚本的 GBDT 代码原样复制后重跑的，重跑的 300 棵曲线和测试 AUC 与参考输出完全一致。单棵树按 CART 的做法另写：15 列原始单位，候选切点取相邻取值的中点，Gini 不纯度；第 01 节那棵最多 3 层、叶子至少 50 个样本，深度表不限叶子大小，剪枝用代价复杂度、按验证集 AUC 挑。Bagging 和随机森林各 100 棵，自助采样，种子固定，长满（森林另有一组叶子至少 5 个样本），森林每次切分随机看 4 列。只用 night、long 两列的逻辑回归用全量梯度下降训到收敛；逻辑回归对样本 2462 的概率按参考配方重训得到。AUC 和对数损失的算法与参考脚本相同，对数损失把概率截在 10⁻¹² 到 1 − 10⁻¹²。误差区间引自评估那一页。三个库和 GBDT + 逻辑回归的描述来自各自的论文和文档，没有在这份数据上跑这几个库。

大语言模型：一个字一个字地预测

前几篇的模型对一次曝光只算一个数：这首歌会不会被听满 30 秒。大语言模型做的是同一类事：读进到目前为止的文字，给词表里的每个 token 各算一个概率，挑一个接在后面，再算下一个。这一页先用这个知识库自己的文字数出一个最简单的语言模型，看清"预测下一个字"是什么意思；再把它换成神经网络，看大模型怎么训练、怎么生成，以及为什么会说得通顺却说错。

词表里每个字一个概率1,502 个
→
最大的是"器"44.2%
→
下一个字真是"器"时的损失0.82

数字来自一个三元模型：把这个知识库在 AI 这一组之前发布的 35 个页面的正文取出来，共 273,766 个字符，数每两个字后面跟着什么。"解码"出现了 292 次，其中 129 次后面是"器"；0.82 是 −ln 0.442，第 09 节讲它是什么。这一页是总览图里"大模型"那一站的展开。

01预测下一个 token

前几篇的模型回答的是一道是非题：把这首歌推给这位用户，他会不会听满 30 秒。输入是 15 个特征，输出是 0 到 1 之间的一个概率。逻辑回归、树模型和小神经网络，形状都是这样。

语言模型回答的是一道选择题：给出到目前为止的文字，下一个 token 是什么。token（中文也叫词元）是模型读写文字的单位，可以是一个字，也可以是半个词，第 05 节细说。所有可能的 token 列成一张表，叫词表（vocabulary）。模型的输出是词表里每个 token 各一个概率，加起来等于 1。

前几篇：推荐一首歌这一页：写下一个字
一条样本一次曝光文字里的一个位置
输入15 个特征：曲风偏好、歌曲热度、是否关注歌手……这个位置前面的文字
标签听满 30 秒记 1，否则记 0这个位置上实际出现的 token
输出1 个概率词表里每个 token 一个概率
标签从哪来播放日志，要等用户真的听过文字本身

最后一行是关键。特征和样本那一篇里，一条正样本要等曝光发生、用户播放之后才有。语言模型的标签是现成的：拿一段真实的文字，每个位置都是一条样本，前面的字是输入，这个位置上的字就是答案。这叫自监督（self-supervised），监督信号来自数据自己，不用人标。

DNS 那一页的开头有一句"每次连接之前都要先做它。"单拿出来看，12 个字符就是 12 条样本：

样本输入：前面的字标签：下一个字
1每次
2每次连
3每次连接
………
11每次连接之前都要先做它
12每次连接之前都要先做它。

一本书几十万字，就是几十万条样本；网上的文字，就是上万亿条。前几篇的 3,000 条曝光要靠用户一条条产生，这里的样本多到用不完。预测在预测什么，在大模型这里的答案就是：下一个 token。推荐也借了这个思路：把一个人的听歌记录当成一句话，预测下一首（推荐那一篇的模型演进）。

02先数数：n-gram 模型

最简单的语言模型不用训练，只用数数：拿一大段文字，统计每个字后面跟过什么字、各几次。

P(下一个是"器" | 前面是"解码")
  = "解码器"出现的次数 ÷ "解码"出现的次数
  = 129 ÷ 292 = 0.442

只看前 1 个字叫二元模型（bigram），看前 2 个字叫三元模型（trigram），统称 n-gram：用前 n − 1 个字预测第 n 个。这个办法很老，1948 年香农在《通信的数学理论》里就按英文字母和单词的统计造过句子。

03让数数的模型写几句

有了下一个字的分布就能写字：按概率抽一个字，接上，再看最后两个字，再抽。用 Python 的 random.Random(2026) 固定随机种子，从"解码"和"数据"开始各写 4 段，抽到段落结束（下面记作 ⏎）或者写满 40 个字就停：

  • 整句没有意思。第二段二十几个字里，从解码跳到混音，又跳到路由器。它只记得最后两个字，不知道自己在说什么。

04数数的模型卡在哪

这个模型有三个绕不过去的问题。

没见过的，概率就是 0

"训"和"练"两个字在这 35 页里一次也没出现过。这个模型给它们的概率永远是 0，不可能写出"训练"。"梯度""向量""样本"也都是 0 次。"预测"出现了 14 次，全是"帧内预测""预测方式"这类编解码里的说法，出自 H.264 和 AAC 那几篇。

它知道什么，完全取决于数过的文字。大模型也一样，只是它数过的文字多得多。

看得越长，没见过的越多

多看几个字，预测会准一些。拿 34 页来数，留出 DNS 那一页当测试，看前 0 到 5 个字各试一遍：

"没见过"指的是前面这几个字加上下一个字的组合，在 34 页里一次也没出现过，按次数算概率就是 0。损失越小，说明模型给真实下一个字的概率越大，第 09 节细讲。

看得越长，在数过的文字上越准，因为它几乎是把原文背了下来。换到没见过的一页，看前 2 个字时就有三分之一的位置是没见过的组合，看前 5 个字时是四分之三。这和评估那一篇说的过拟合是一回事：在训练数据上的分数，说明不了新数据上的表现。

表的大小也在涨。1,502 个字，前两个字的组合理论上有 1,502² ≈ 226 万种，再接一个字就是 1,502³ ≈ 34 亿格。35 页里填上的只有 113,399 格，约三万分之一。文字再多也填不满。

两个字以外的都看不见

"音频解码器输出"和"视频解码器输出"，接下来一个该说 PCM，一个该说 YUV。三元模型只看得到最后的"输出"两个字，两种情况给出的概率完全一样。第 03 节写着写着就换话题，也是这个原因。

补救的办法有过不少，比如没见过三个字的组合就退回去看两个字，第 09 节会用到。真正绕过去靠的是神经网络，它做了两件事：

  • 把字变成向量。"解码"和"编码"后面跟的字很像，排第一的都是"器"（44.2% 和 29.4%），可在计数表里它们是毫不相干的两行，各数各的。神经网络给每个 token 学一个向量，用法相近的 token 向量也相近，在一个上面学到的规律会用到另一个上。2003 年 Bengio 等人提出神经网络语言模型，出发点就是这个。
  • 用注意力看全部上文，不只是最后两个字。见第 07 节。

05token：字、词，还是半个词

上面的模型一个字符算一个 token。好处是词表小，什么文字都拼得出来；代价是序列长，一句话要预测很多步，每一步带的信息也少。按词切可以短很多，但词表会大到几十万，新词、错别字、代码里的变量名还是切不出来。

现在的大模型用折中的子词（subword）：常见的词整个算一个 token，少见的拆成几块。最常用的切法是 BPE（byte pair encoding，字节对编码），原本是一种压缩算法，2016 年 Sennrich 等人把它用到了机器翻译上。它的训练只有一句话：找出语料里出现次数最多的相邻两个 token，合并成一个新 token，重复几千到几万次。

在这个知识库的正文上跑一遍。为了看得清楚，只在连续的汉字之间合并，英文、数字和标点保持一个字符一个 token。最先合并出来的 12 个，括号里是合并时的次数：

一个（1,092）、字节（723）、地址（659）、路由（439）、服务（391）、没有（372）、服务器（362）、手机（351）、什么（335）、里的（327）、数据（316）、路由器（315）。"服务器"是第 7 次把已经合并好的"服务"和"器"再合一次得来的，"解码"排在第 17 次。

"音频解码器输出"切成 音频|解码器|输出，3 个 token。第 07 节就拿它手算。

  • 合并只看次数，不看意思。"里的""的是""要先"也成了 token，它们不是词典里的词。
  • 大模型的 BPE 从字节开始，不从字开始。UTF-8 里一个常用汉字占 3 个字节，这 273,766 个字符一共是 601,942 字节。GPT-2 的词表是 256 种字节，加上合并出来的 5 万个，再加一个文本结束标记，共 50,257 个。语料里常见的汉字会合成一个 token，少见的字可能还是两三个。同一段中文在不同模型里切出来的 token 数可以差很多，要用那个模型自己的分词器去数。
  • LLaMA 和 Llama 2 也用 BPE，词表 32k 个。它们把数字拆成单个数字，遇到词表里没有的字就退回 UTF-8 字节。
  • 词表大小是个取舍。词表大，同样的文字 token 少，生成的步数少，上下文窗口（第 13 节）里装得下的文字多；但每个 token 在输入和输出各要一行参数，见下一节。

06换成神经网络

神经网络语言模型的输入输出和计数表一样：进去前面的 token，出来词表上的概率。区别在中间。GPT、LLaMA 用的都是 Transformer（2017 年 Vaswani 等人提出），从下往上分四步：

  • 查嵌入表。每个 token 是一个编号。嵌入表（embedding）是一个"词表大小 × d"的矩阵，编号是几就取第几行，得到一个 d 维向量。d 在 LLaMA-7B 里是 4,096，在 GPT-3 里是 12,288。光有向量分不出谁在前谁在后，还要加上位置信息（第 07 节末尾）。
  • 过 N 个 Transformer 块。每个块先做自注意力，让每个位置从前面的位置取信息；再过一个前馈网络，每个位置各算各的。块的输入和输出形状相同，可以一个接一个叠上去，GPT-3 叠了 96 个。从下往上算一遍，就是前向传播。
  • 算 logit。最后一个位置的向量乘一个"d × 词表大小"的输出矩阵，词表里每个 token 得到一个分数，叫 logit。每个分数都是向量各维的加权求和，每个 token 有自己的一组权重。
  • softmax 变成概率。pi = ezi ÷ (ez1 + ez2 + … + ezV)，z 是 logit，V 是词表大小。取指数让每个数变成正的，除以总和让它们加起来是 1，分数高的概率大。
只有两类时，把另一类的分数定为 0，softmax 就是 ez ÷ (ez + 1) = 1 ÷ (1 + e−z)，正是前几篇的 sigmoid。逻辑回归就是一个只有两个 token 的输出层。

第 04 节的稀疏问题在这里缓解了：softmax 给出的概率不会是 0；一个没见过的组合，只要里面的 token 和见过的 token 向量相近，算出来的概率也相近。推荐那一篇给用户和歌曲的 ID 查表得到向量，是同一个办法。代价是参数多了：LLaMA-7B 的嵌入表是 32,000 × 4,096 ≈ 1.3 亿个参数，输出矩阵也是这个形状。

07自注意力：手算一遍

自注意力（self-attention）解决的是计数模型的第三个问题：让一个位置用上前面任何位置的信息，而且自己决定用多少。

每个位置的向量先乘三个学出来的矩阵，变成三个向量：

  • 查询 q（query）：我在找什么样的信息；
  • 键 k（key）：我这里有什么样的信息；
  • 值 v（value）：被选中时我交出去的内容。

位置 i 给位置 j 打的分，是 qi 和 kj 的点积（对应的数相乘再相加）除以 √d。每一行分数做 softmax 得到权重，再用权重把各位置的 v 加起来，就是位置 i 的输出。

拿第 05 节切出来的"音频|解码器|输出"算一遍。d = 4，√d = 2。真实模型里 q、k、v 由向量乘矩阵得到，每个头有 64 到 128 维，每一维也没有说得出的含义；下面这些是为了手算编的小整数：

位置tokenqkv
1音频(1, 0, 0, 1)(1, 0, 1, 0)(2, 0, 0, 1)
2解码器(0, 2, 0, 0)(0, 1, 0, 1)(0, 1, 1, 0)
3输出(2, 0, 2, 0)(0, 0, 1, 1)(0, 0, 1, 0)

算第 3 个位置"输出"。它要预测下一个 token，得知道前面说的是音频还是视频。

① 点积      q₃·k₁ = 2×1 + 0×0 + 2×1 + 0×0 = 4
            q₃·k₂ = 2×0 + 0×1 + 2×0 + 0×1 = 0
            q₃·k₃ = 2×0 + 0×0 + 2×1 + 0×1 = 2
② 除以 √d   4、0、2  →  2、0、1
③ 掩码      位置 3 是最后一个，前面都能看，三个分数都保留
④ softmax   e² = 7.389，e⁰ = 1，e¹ = 2.718，合计 11.107
            权重 = 7.389 ÷ 11.107，1 ÷ 11.107，2.718 ÷ 11.107
                 = 0.665，0.090，0.245
⑤ 加权求和  0.665 × (2, 0, 0, 1) + 0.090 × (0, 1, 1, 0) + 0.245 × (0, 0, 1, 0)
            = (1.33, 0.09, 0.33, 0.67)

"输出"把三分之二的注意力给了"音频"，它的新向量大半来自"音频"交出的 v。后面的层拿这个向量去预测下一个 token，就有了分清 PCM 和 YUV 的依据。前两个位置也这样算，三行合起来是一张权重表：

  • 因果掩码。被挡住的分数在 softmax 之前设成负无穷，e 的负无穷次方是 0。生成时后面的字还不存在；训练时整段文字一次喂进去，不挡住的话，模型看一眼下一个字就把答案抄了。
  • 为什么除以 √d。不除的话，第 3 行的权重是 0.867、0.016、0.117，尖得多。d 有上百维时，softmax 会几乎只剩一个 1、其余都是 0，梯度很小，学不动。原论文的理由是：q、k 每一维的方差为 1 时，点积的方差是 d，除以 √d 正好拉回 1。
  • 距离不要紧，顺序要另外告诉它。打分只看 q 和 k 合不合，"音频"在 2,000 个 token 之前也一样算。反过来，把前面的 token 换个次序，加权和也不变，所以第 06 节要在向量里加位置信息：GPT-2、GPT-3 给每个位置学一个向量，LLaMA 用旋转位置编码（RoPE）。
  • 多头。真实模型同时做很多组注意力，每组有自己的三个矩阵，叫一个头（head）。GPT-3 每层 96 个头，每个头 128 维。各个头关注什么是训练出来的，不是人定的。

08一个 Transformer 块

真实的块在注意力外面还有几层包装。以 GPT-3 为例，d = 12,288：

① 归一化
  1. 调到均值 0、方差 1
  2. 再乘一组缩放系数
② 多头注意力
  1. 96 个头各算一遍
  2. 拼回 12,288 维
③ 加回输入
  1. 加上 ① 之前的向量
  2. 这叫残差连接
④ 前馈网络
  1. 归一化，放大再缩回
  2. 结果再加回输入
  • 归一化（layer normalization）和残差连接（residual）是让几十上百层训得动的两样结构，神经网络那一篇讲过。残差把一步的输入直接加到输出上，每一步只学"在原来的基础上改多少"，梯度也多了一条传回底层的近路。LLaMA 的归一化用的是更简单的 RMSNorm。
  • 前馈网络（feed-forward）是每个位置单独过的两层小网络：先放大到 4 倍宽（GPT-3 是 49,152 维），过一个非线性函数，再缩回来。它和那一篇的 15 → 16 → 8 → 1 是同一种东西，只是宽得多。非线性函数 GPT 系列用 GELU，LLaMA 用 SwiGLU。

参数几乎全在矩阵里，数一数：

部分矩阵参数
注意力q、k、v 和输出各一个 d × d4d²
前馈网络d × 4d 和 4d × d8d²
一个块归一化和偏置很少，略去约 12d²

GPT-3：12 × 12,288² × 96 层 ≈ 1,739 亿；嵌入表 50,257 × 12,288 ≈ 6.2 亿，位置表 2,048 × 12,288 ≈ 0.3 亿；合计约 1,746 亿。论文附录的算力表里，GPT-3 的参数量写的就是 174,600 百万，对外叫 1750 亿。三分之二的参数在前馈网络里。

一个大模型就是这几种矩阵按固定的形状排好，再重复几十遍。结构一页纸画得下，那 1,746 亿个数才是它学到的东西。

09训练：还是对数损失

训练要一个损失函数，衡量模型给的概率有多差。用的就是前几篇的对数损失（log loss），在这里通常叫交叉熵（cross-entropy）：

损失 = −ln(模型给真实下一个 token 的概率)

二分类时，标签是 1 损失是 −ln p，标签是 0 损失是 −ln(1 − p)，两种情况都是"−ln（给真实结果的概率）"。语言模型只是把两个可能的结果换成了 1,502 个或者 5 万个。用三元模型的数字算三个位置：

上文真实的下一个字模型给它的概率这一步的损失
解码器0.4420.82
解码顺（"解码顺序"）0.0273.60
解码一个它在"解码"后面没见过的字0无穷大

猜对了又有把握，损失小；真实的字只分到一点概率，损失大；给了 0，损失无穷大，所以真正用的模型绝不能把概率给成 0。完全不懂、每个 token 给一样的概率时，损失是 ln（词表大小）：前几篇的 2 类是 ln 2 = 0.693，本页的 1,502 个字是 7.31，LLaMA 的 32k 个 token 是 10.37，GPT-2 的 50,257 个是 10.82。

拿第 04 节留出的 DNS 那一页打分：34 页统计，测试页有 15,783 个位置。e 的损失次方叫困惑度（perplexity），可以读成"相当于每一步在多少个字里平均地瞎猜"：

模型测试页上的平均损失困惑度
每个字一样的概率7.311,493
只看单字频率，加一平滑5.53252
三元，直接用次数无穷大无穷大
三元、二元、单字按 0.6、0.3、0.1 混合3.6036.5

直接用次数时，测试页上 34.1% 的位置概率是 0。加一平滑：每个字的次数都加 1。混合：三个模型的概率按权重相加，两字开头没见过时，它的权重让给二元；权重没有调过，换成 0.5、0.4、0.1 是 3.59。这里的词表是 34 页里的 1,491 个字加段落结束，再加一个"没见过的字"，共 1,493。

神经网络怎么训

和前几篇一样：前向算出每个位置的概率，算损失，反向传播求出每个参数的梯度，沿梯度的反方向改一小步（梯度下降，总览第 7 站）。实际用的是 Adam 这类梯度下降的改进版。

不同的是规模，还有一点：一段 2,048 个 token 的文字，一次前向就能得到 2,048 个位置的损失。因果掩码保证每个位置只看得到自己前面，所以所有位置可以同时算，不用一个一个来。生成时做不到，下一个 token 要等上一个抽出来。

10生成：从分布里挑一个

训练好的模型，对任何上文都能给出一张概率表。从表里怎么挑，叫解码策略。这一步不改模型，只改怎么用它的输出。下面都用三元模型在"解码"之后的真实分布演示。

贪心：每次取最大的

结果是确定的，同一个开头永远写出同一句。问题是容易绕圈。不让它停（跳过段落结束），从 4 个开头各写 40 个字：

解码器的 MAC 地址，不是 100 ms 的 MAC 地址，不是 100 ms 的
数据，解码器的 MAC 地址，不是 100 ms 的 MAC 地址，不是 100 m
网络上的 MAC 地址，不是 100 ms 的 MAC 地址，不是 100 ms 的
播放器的 MAC 地址，不是 100 ms 的 MAC 地址，不是 100 ms 的

四个开头掉进了同一个圈。每一步都是"最可能的字"，连起来是一句废话。大模型也有这个毛病：Holtzman 等人 2020 年的论文指出，按最大概率解码出来的文字平淡，而且会反复重复。

按概率抽，用温度调形状

把每个概率取 1/T 次方，再重新归一化，等价于把 logit 除以 T 再做 softmax。T 叫温度（temperature）：

"解码"之后T = 0.5T = 1（原样）T = 2

段落结束4.0%9.2%6.0%

之0.7%3.8%3.8%
其余 43 种3.1%37.7%72.5%
凑够 90% 要几种12139

T 小于 1 把高的拉得更高，T 大于 1 把分布压平，T 趋近 0 就成了贪心。同一个种子，各抽 3 段：

T = 0.5   解码器不支持。⏎
          解码器自己的 IP 的 ABIC 地址⏎
          解码后不再涨⏎

T = 2     解码器处理是两个⏎
          解码，19（9）。路上的线路稳定地址存不一致时，很多城市，甚至公网⏎
          解码之后。VP9、G.95448⏎

低温度稳，但单调；高温度花样多，错字和乱码也多。

只在前几名里抽

  • top-k：只留概率最大的 k 个，重新归一化再抽。k = 3 时，"解码"之后只剩器 75.4%、段落结束 15.8%、后 8.8%。
  • top-p（nucleus sampling，核采样）：从大到小往上加，加够 p 就停，只在这些里抽。p = 0.9 要留 21 种，p = 0.5 只留 2 种。分布尖时留得少，平时留得多，比固定的 k 灵活。

温度和 top-p 常常一起用：温度定形状，top-p 砍掉长尾里那些不靠谱的字。同一个问题问两次答案不一样，原因就在这一步的抽签。要稳定的输出，比如抽取字段、写代码，把温度调低。

11预训练之后：指令微调和偏好

只做过"预测下一个 token"的模型叫基座模型（base model）。它会续写，不一定会回答。网上的文字里，一个问题后面常常跟着另一个问题，所以问它"DNS 是什么？"，它可能接着再列几个问题。InstructGPT 的论文直接说，预测网页上的下一个 token，和按用户的意思把事情做好，不是同一个目标。

InstructGPT 把基座模型调成助手，在预训练后面接了三步：

① 预训练
  1. 海量文字
  2. 预测下一个 token
② 指令微调
  1. 人写的提问和好回答
  2. 还是预测下一个 token
③ 奖励模型
  1. 人给几个回答排先后
  2. 学一个打分的模型
④ 强化学习
  1. 按奖励模型的分数调参数
  2. 不许离 ② 太远
  • 指令微调还是同一个损失。数据换成人写的示范：一个提问，一个好回答。InstructGPT 的示范数据约 1.3 万条提问。现在的对话模型把多轮对话拼成一段文字，用几个特殊 token 标出谁在说话、回答在哪里结束。模型学会了在回答写完时输出结束标记，所以知道什么时候停。
  • 奖励模型和前几篇是同一个问题。给同一个提问的两个回答 A、B，预测"人更喜欢 A"的概率：p = sigmoid（A 的分数 − B 的分数），损失是 −ln p。这就是前几篇的 sigmoid 加对数损失，标签从"有没有听满 30 秒"换成了"人选了哪一个"。InstructGPT 让标注员一次给 4 到 9 个回答排序，再拆成两两比较。
  • 强化学习这一步没有标准答案。模型自己写，奖励模型打分，用 PPO 算法往高分的方向调。同时加一项惩罚，不许它离指令微调后的模型太远，否则它会去钻奖励模型的空子，写出分数高、但人并不想要的东西。
  • 效果。InstructGPT 的论文里，标注员更喜欢 13 亿参数的 InstructGPT 的回答，而不是 1,750 亿参数的 GPT-3。
  • 也有省掉奖励模型的做法，比如 DPO（Rafailov 等，2023），直接拿成对的偏好数据调语言模型。

这几步改的是它更愿意说什么、用什么口气说。底下还是那台预测下一个 token 的机器。

12内存和速度：几道乘法

模型就是一堆数。它占多少内存，就是参数个数乘每个参数的字节数：

每个参数存成字节DNN，401 个参数7B 模型，70 亿个
32 位浮点（FP32）41,604 字节28 GB
16 位浮点（FP16、BF16）2802 字节14 GB
8 位整数1401 字节7 GB
4 位整数0.5约 200 字节3.5 GB

"7B"是档位的名字。LLaMA-7B 的论文里写的是 6.7B，用 16 位存是 13.4 GB。

  • 量化。从 16 位压到 8 位、4 位叫量化（quantization）：把一小组参数映射到 256 个或 16 个整数档位上，每组再记一个缩放系数。4 位的文件会比 3.5 GB 略大，多出来的就是这些系数。精度有损失，损失多少看模型和方法。
  • KV cache。生成第 n 个 token 时，要和前面所有 token 的 k、v 做注意力。前面的 k、v 不会再变，算一次存起来，这叫 KV cache。按 LLaMA-7B 的形状（32 层，每层 4,096 维）、16 位存：每个 token 每层存 k 和 v 各 4,096 个数，一共 2 × 32 × 4,096 = 262,144 个数，524,288 字节，约 0.5 MB。上下文 2,048 个 token 是 1.07 GB，4,096 个是 2.15 GB，和 4 位量化后的模型本身是一个量级。
  • 算力。每生成一个 token，每个参数做一次乘法、一次加法，7B 模型约 140 亿次浮点运算。
  • 速度上限常常卡在内存带宽。每生成一个 token，全部权重都要从内存读一遍。4 位的 7B 模型是 3.5 GB，假如内存每秒能读 50 GB，每秒最多生成约 14 个 token，算得再快也没用。读提示词（prefill）不一样：提示词的 token 全都已知，可以像训练时那样一次并行算完，所以读一段长提示词比生成同样长的回答快得多。

和前几篇比一比：推荐里的排序模型给每首候选歌算一个概率，每首只算一次（总览的上线一站，推荐那一篇的线上部分）。大模型回答 500 个 token，要把整个网络连着算 500 遍，每一遍都要等上一遍抽出的 token。

Android 上的大模型

小网络在手机上怎么跑，见神经网络那一篇。大模型目前有两条路。一条用系统的：部分机型的 AICore 系统服务里带着 Google 的 Gemini Nano，App 通过 ML Kit 的 GenAI API 调用，有摘要、校对、改写、图片描述这些现成接口，也可以用 Prompt API 自己写提示词。模型由系统下载和更新，不算在 App 的存储和运行内存里；但不是每台手机都有，要准备没有它时的退路，比如改走云端。

另一条是 App 自己带模型。Google 的 LiteRT-LM 建在 LiteRT（TensorFlow Lite 的后继）之上，能跑 Gemma 这类开放模型，会话、KV cache、流式输出都替你管；开源的 llama.cpp 也能编译到 Android 上。这时模型文件要自己下发，上面那几道乘法就是你的预算：模型、KV cache 和 App 本身都得放进手机内存，生成期间处理器一直在忙，耗电和发热也要算进去。

13为什么说得通顺却会错

回到第 03 节的"解码器依次拆帧头的含义"和第 10 节的"解码器的 MAC 地址"：每三个连着的字都是真的，整句是错的。大模型的错要隐蔽得多，原因是同一个。

  • 每一步只问"接下来什么最像"。回答一个事实问题时，模型没有去哪里查，它在续写一段"像正确答案"的文字。训练文字里反复出现的事实，会把正确的 token 推到很高的概率，所以它常常是对的。很少出现的事实，比如一个冷门 API 的参数、一篇论文的页码，概率分散在很多候选上，它照样抽出一个，写得一样流畅。
  • 没有"不知道"这个默认选项。softmax 总会给出一个分布，抽样总会抽出一个 token。除非训练时专门奖励过"说不知道"，它更倾向于给一个像样的答案。
  • 一步编错，后面跟着编。抽出来的 token 会接进上文，成为下一步的输入。前面编出一个名字，后面会顺着它往下编。
  • 知识停在训练数据截止那天。参数训完就固定了，之后发生的事它不知道，除非写进上文。

上下文窗口

上下文窗口（context window）是模型一次能看到的最大 token 数：GPT-2 是 1,024，GPT-3 和 LLaMA 是 2,048，Llama 2 是 4,096。窗口里的任何位置，注意力都能直接看到；窗口外的完全看不到。这和三元模型只看得到 2 个字是同一种限制，只是宽得多。对话太长时，最早的内容要么被截掉，要么被压成摘要。

这也解释了为什么把资料贴进提示词有用：原文就在窗口里，注意力可以直接从那里取，不用靠参数里模糊的统计。先检索出相关的文档、再交给模型回答的做法，叫检索增强生成（RAG）。

所以大模型的回答要当作"一段很可能对的文字"来用：常见的知识大多可靠；冷门的名字、数字、出处要自己核对；需要准确的事实，就把原文放进上下文。

14常见坑

现象原因处理
一本正经地编出不存在的 API、参数或出处它在续写"像答案的文字"；冷门的事实在训练文字里太少，概率分散在许多候选上，抽中哪个都写得一样流畅把官方文档贴进上下文；要出处就自己点开核对
同一个问题问两次，答案不一样生成时按概率抽样，温度大于 0要稳定输出就把温度调低；重要的结论多问几次，看是否一致
输出绕圈，同一句重复好几遍；或者温度一高就满篇乱码贪心和低温度容易掉进高概率的循环；T 大于 1 又把长尾的字抬了起来，见第 10 节适当的温度加 top-p；有的接口有重复惩罚参数
对话一长，忘了前面说过的话超出上下文窗口，早期内容被截掉或被压成摘要关键要求放在最近的消息里；长资料先摘要

问最近的事，答得很肯定，内容却过时了参数停在训练数据截止的那天把最新资料放进上下文
